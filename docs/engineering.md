# 多工厂生产规划：工程设计与验证

## 业务场景与决策范围

制造企业需要为多个既有工厂制定分产品、分月份的生产计划。不同工厂的产能和产品兼容性存在差异，产品又有不同需求、售价、成本及单位排放系数。决策者需要比较利润、产能利用率和碳排放之间的折中方案。

当前工程是该场景的**合成数据优化原型**：使用 5 个工厂、8 类产品和可配置月份数，尚未接入企业业务数据或生产系统。这里的“生产布局”指既有工厂间的产量分配；工厂选址、产线投资、工序排序、库存结转、物流及交期尚未建模。

## 模型与求解流程

每个候选个体包含连续变量 `x[工厂, 月份, 产品]`。约束修复先清除负产量和不兼容产量，再对超过工厂月产能的产量按比例缩放。产品需求按月在所有工厂之间共享，超出需求的产量不产生销售收入，但仍计入生产成本及碳排放。

| 决策目标 | 当前计算方式 | 输出方向 |
|---|---|---|
| 利润 | 每产品月的销售收入减总生产成本 | 最大化 |
| 产能利用率 | 全部产量除以可用总产能 | 最大化 |
| 生产碳排放 | 各产品产量乘单位排放系数后汇总 | 最小化 |

进化过程使用锦标赛选择、逐变量算术交叉、稀疏扰动和约束修复；候选方案经非支配排序，再使用归一化目标与参考方向的距离选择。该方法受 NSGA-III 启发，并非标准 NSGA-III 的完整实现。详细公式、合成参数与算法边界见 [model.md](model.md)。

最终 CSV 仅导出非支配方案的利润、利用率、排放和等级；尚不包含每个方案的详细产量矩阵，因此暂时不能直接作为生产执行计划。

## 并行设计

| 后端 | 工作划分 | 数据与同步 |
|---|---|---|
| Serial | 顺序评估每个个体 | 统一评估函数，作为正确性和计时基准 |
| OpenMP | 按个体静态分配循环迭代 | 每个迭代写入独立结果，无嵌套线程团队 |
| MPI | 根进程生成种群并广播，所有 rank 评估本地分区 | `MPI_Gatherv` 按各进程数量与位移汇总结果；适配不整除情况 |
| PPL | 使用 `parallel_for` 分配个体评估 | Windows/MSVC 运行时调度，共用评估函数 |

初始化、父本选择、交叉、变异、修复和全局选择由主线程或 MPI 根进程执行，**并行范围是个体评估**。这使同一随机种子不依赖线程调度，但也意味着遗传操作和选择仍限制整体扩展性。

## 验证状态

- 模型测试覆盖约束修复、修复幂等性、目标函数样例、支配关系与选择数量；同时检查非法参数。
- 测试脚本使用固定随机种子，比较非支配目标 CSV：串行与 OpenMP、PPL，以及 19 个个体 / 3 个 MPI 进程的结果逐字节一致。
- [GitHub Actions 验证记录](https://github.com/shuke-dsj/GreenPlan-Parallel-/actions/runs/44057207682)：Linux OpenMP/MPI 与 Windows OpenMP/PPL 通过。Linux MPI 测试允许超订阅，以在较少 CPU 槽位上测试 3 进程；它不用于性能基准。
- 这些检查说明所测输入下的实现一致性，不证明优化结果为全局最优，也不代表覆盖所有平台和数据规模。

## 性能测量与限制

基准原始数据见 [benchmark-local.csv](benchmark-local.csv)。本机以 Windows、MinGW GCC 8.1、120 个体、30 代、24 个月及 3 个随机种子测试；串行平均总时间约 0.05727 秒，OpenMP 4 线程约 0.05723 秒。任务时间较短、未固定 CPU 亲和性且没有预热轮次，噪声较大，不能据此声称显著加速。

总时间包括初始化、进化、评估、选择和结果写出，不包括程序启动及 `MPI_Init`。`evaluation_seconds` 只累计每代子代评估，不含初始种群评估；MPI 评估计时还包括广播与收集，不能解释为纯计算时间。加速比为串行时间除以并行时间，并行效率为加速比除以资源数。

非支配排序为 O(N²)，全局选择集中执行；MPI 每代广播完整决策数据，规模增加时可能出现复制、通信和根进程瓶颈。并行评估的收益取决于个体评估成本与同步通信开销的比例。

## 向企业应用扩展

1. 接入经过授权的企业或公开数据，定义单位、时间粒度、数据质量检查和缺失值处理。
2. 导出完整产量决策矩阵，并建立方案追溯、约束诊断与业务审核流程。
3. 按需求扩展库存、物流、交期、整数批次和产线约束；若要研究选址或产线布局，需新增相应决策变量与约束。
4. 对照标准 NSGA-III、基线算法和小规模已知最优实例，报告可行率及 HV/IGD 等指标。
5. 使用更高计算负载、多次重复和分阶段计时评估扩展性，先定位热点再考虑并行化遗传操作及降低 MPI 通信量。
